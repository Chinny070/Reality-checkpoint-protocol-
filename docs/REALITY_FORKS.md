# Reality Forks

For each claim, validators classify each associated source independently. A fork requires opposing `SUPPORTED` and `CONTRADICTED` findings from distinct clusters whose relationships are both `INDEPENDENT`. SAME_OWNER, SYNDICATED, DERIVATIVE, CITES_OTHER, UNKNOWN_RELATIONSHIP, unavailable, and unknown findings cannot qualify either side. Cluster IDs are derived from the registrable domain. The deterministic contract sets `state_status=DISPUTED` and `divergence_status=CONTRADICTORY_REALITY` for a qualifying fork, even when the model proposes a softer label. A model-level fork label without opposing qualified findings is ignored. Nonqualifying contradictory findings cannot override an independently supported state.

The contract derives fork state from bound source findings, not model summary labels. If all informative findings contradict, state is `DISPUTED` because a previously supported claim has failed, while divergence remains `CONSISTENT`: there is no opposing source reality. Unknown and unavailable findings do not count as evidence for either side. An unsupported model fork label cannot manufacture a fork; an unsupported insufficiency label cannot erase a deterministic evidence floor.

Other typed outcomes include minor/material divergence, insufficient independence/evidence, and external failure. The system never averages opposite claims into positive certainty. Consumers should reject disputed and unavailable certificates unless their own frozen policy explicitly defines another route.
